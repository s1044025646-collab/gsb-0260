# 人民币中文大写金额转换与规范写法核验后端

仅提供 **HTTP API** 与 **命令行（CLI）**，无前端。使用 TypeScript + Node.js 内置
`node:sqlite`（无需原生编译、无需 Docker/WSL、不访问任何在线服务），在 Windows 本地运行。

- 规则版本：`RMB-CAPS-RULES-1.0`（随每次转换、核验与历史记录一起保存）
- 范围：`0.00` ～ `999999999999.99`（零到九千九百九十九亿九千九百九十九万九千九百九十九元九角九分）
- 不支持：负数、外币、票据审批、会计记账、民间简写、繁体异体字（如“萬/貳/圓”）。

## 唯一规范化口径

1. 整数数字使用：`零壹贰叁肆伍陆柒捌玖`，位值单位 `拾佰仟万亿`，小数单位 `角分`，货币单位 `元`。
2. 整数部分从右向左每 **四位一组**：个组（无单位）、万组（`万`）、亿组（`亿`）；组内按 `仟/佰/拾/个` 输出。
3. 组内连续的零只写一个，组尾零省略。
4. **跨组补零**：两个非空组之间若存在空组（如 `100000001` 的万组为空），或较低一组不足四位（千位为 0），在跨组单位后补一个 `零`。
5. 整数无角无分时以 **`元整`** 结尾；零金额为 **`零元整`**。
6. 有分无角时在 `元` 后补 `零`：`0.07` → `零元零柒分`，`1001.05` → `壹仟零壹元零伍分`。
7. **固定的“整”字规则**：只要有“分”就不加“整”；有角无分加“整”（`0.60` → `零元陆角整`）；无角无分加“整”。
8. 确定示例：
   - `1001.05` → `壹仟零壹元零伍分`
   - `100000001.00` → `壹亿零壹元整`
   - `100010001.00` → `壹亿零壹万零壹元整`
   - `999999999999.99` → `玖仟玖佰玖拾玖亿玖仟玖佰玖拾玖万玖仟玖佰玖拾玖元玖角玖分`

## 输入规则

- 数字金额以 **字符串** 传输，内部不经过浮点数，按字符解析以保留精度。
- 允许并去除 **外围空白**；允许整数前导零（按数值规范化）。
- 小数 **少于两位按补零处理**（`8` → `8.00`，`8.1` → `8.10`）；**超过两位直接拒绝**，不自动舍入。
- 反向核验只接受上述规范写法。可解析但非规范的输入（如漏写跨组零 `壹亿壹元整`）会被拒绝，
  返回错误码 `E_NONCANONICAL` 与正确的规范形式，**不会静默把错写当作成功金额**。

### 错误码

| 错误码 | 含义 |
| --- | --- |
| `E_EMPTY` | 输入为空 |
| `E_INVALID_NUMBER` | 非字符串/非法字符/多小数点/负号等数字格式问题 |
| `E_PRECISION_EXCEEDED` | 小数超过两位，拒绝舍入 |
| `E_OUT_OF_RANGE` | 超出 0 ～ 999999999999.99 |
| `E_ILLEGAL_CHAR` | 大写文字含规范字符集以外的字符 |
| `E_UNIT_ORDER` | 单位次序错误（如 `壹拾佰`、`万` 在 `亿` 前、`角` 在 `元` 前） |
| `E_DUPLICATE_UNIT` | 单位重复（如 `壹佰佰元整`、两个 `元/角/分/万/亿/整`） |
| `E_MALFORMED` | 结构不完整（空组、缺数字、后缀非法等） |
| `E_NONCANONICAL` | 可解析但与规范形式不一致 |
| `E_PARAM` | HTTP 参数错误 |

## 环境与数据

- 需要 Node.js `>= 22.5`（使用内置 `node:sqlite`；已在 Node 25 上验证）。
- 数据默认保存在项目内 `./data/rmb.sqlite`；可用环境变量 `RMB_DATA_DIR` 更改。
- 端口默认选择 **空闲端口**（启动日志打印实际端口）；可用环境变量 `PORT` 指定固定端口。


## HTTP API

| 方法与路径 | 说明 |
| --- | --- |
| `GET /health` | 健康检查 |
| `POST /api/to-chinese` | 入参 `{"input":"1001.05"}`，返回规范金额、规范大写、分组解释 |
| `POST /api/verify` | 入参 `{"input":"壹仟零壹元零伍分"}`，严格核验 |
| `POST /api/batch` | 入参 `{"direction":"amount2cn|cn2amount","items":[{"input":"..."}]}`，1–1000 条；部分失败返回 207，每条带 `index` |
| `GET /api/history?limit=50&direction=amount2cn` | 历史查询 |
| `GET /api/export` | 导出全部记录（含分组解释与错误报告） |

正向/核验成功返回 200；正向/核验单条失败返回 422（仍写入历史）；批量部分失败返回 207。

示例：

```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:<端口>/api/verify -ContentType 'application/json; charset=utf-8' -Body '{"input":"壹佰佰元整"}'
```

## SQLite 表结构

表 `conversions`：`id, direction(amount2cn|cn2amount), input, rule_version, report(JSON), created_at`。
成功与失败报告分别独立落库，失败条目不覆盖成功报告；重启后历史与解释仍可读取。

## 测试基准

`src/test/core.test.ts` 使用人工固定的金额—大写文字对（含零、拾、整百整千、`10001`、
`100010001`、最大值、小数零、非法单位顺序），并在 `0..20001` 全部整数与角分采样上做
**带独立预期**的双向验证（固定基准 + 双向回环），而非仅靠编码解码往返。
